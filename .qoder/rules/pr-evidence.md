# PR 证据规范（交付验收门禁）

本仓库由 Agent 交付、人类做证据审查。每个 PR 都必须让审查者在不读 diff 的情况下判断「这个改动可信吗」。

## 硬性要求

PR 正文**先写入 `.qoder/pr-body.md`**，再用 `gh pr create --body-file .qoder/pr-body.md` 提交。
禁止用 `--body "..."` 内联正文。`.qoder/hooks/pr_evidence.py` 会拦截不合规的提交。

正文必须包含以下三段二级标题，缺一即被阻断：

```markdown
## 行为变更
改动了哪个函数的哪种输入下的行为，改前 vs 改后分别得到什么。
给出具体数值/输出，不要写"修复了一个 bug"。

## 验证证据
实际执行过的命令与其输出摘要。必须包含测试命令、通过/失败数量。
未执行过的验证不得写进这一段。

## 剩余限制
未覆盖的边界、未修改的相邻问题、性能或兼容性隐患、需要人工决定的事项。
确实没有限制时，说明你从哪些角度确认过，而不是只写"无"。
```

`行为变更` 与 `验证证据` 正文各不少于 15 字符，`剩余限制` 不少于 8 字符，过薄会被门禁拒绝。

## 禁止事项

- 禁止合并 PR、禁止批准 PR（`gh pr merge` / `gh pr review` 已在 settings.json 中 deny）。合并永远由人类在 GitHub 网页上完成。
- 禁止 `git push --force`、`git reset --hard`。
- 禁止为了让测试变绿而修改测试断言，除非有明确规格依据，且必须在「剩余限制」中说明。
- 禁止扩大任务范围：只处理派发的那一个任务，顺手重构会被视为越界。

## 任务边界

一次只接一类任务：修复一个已复现的范围明确的 Bug，或为某个已有函数补充单元测试。
开始前先跑出红灯/基线，把原始输出留在「验证证据」里。
